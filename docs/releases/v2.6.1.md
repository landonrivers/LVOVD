# LVOVD v2.6.1 — Runtime checks, removal status, and shorter playlist pauses

This maintenance patch keeps the [v2.6.0 Local Media Workbench & Batch Processing](v2.6.0.md) feature scope, addresses two setup and status issues, and reduces the wait between playlist items.

## FFprobe setup and runtime status

Local Media requires FFprobe to inspect sources and validate results. Quick Start now includes `ffprobe -version`, and Runtime status reports FFprobe alongside Node, yt-dlp, and FFmpeg. A missing or failing FFprobe check explains how to fix PATH and recheck; the launcher warns while keeping ordinary URL Download available.

Tool version checks have a five-second deadline and a shared 256 KiB stdout/stderr limit per process. Failed probes request termination, allow bounded termination grace, and settle even if process pipes never close. Tool errors use short status explanations instead of raw diagnostics or executable paths. These checks do not change Preview, source acquisition, or processing commands.

`GET /api/health` adds `ffprobe` using the existing `{ installed, version?, error? }` tool-status shape. Existing fields remain available; no migration is needed.

## Delayed Remove File responses

An old Remove File response could restore a cleanup sentence after newer collection updates had already cleared the cleanup. Delayed errors could also restore an entry that the server had removed.

Removal responses now stay associated with their originating collection, connection, file, and operation. Newer collection updates remain authoritative for membership and cleanup. A late acknowledgement or error cannot restore removed files, overwrite newer status, or change another file's selection. Cleanup that is still outstanding remains reachable through the existing retry controls.

The delayed-removal presentation limitation noted in the v2.6.0 release notes is resolved by this patch.

## Shorter playlist pauses

Normal playlist downloads and playlist imports into Local Media now pause for a randomized 0.5–1 second between items, reduced from 5–10 seconds. The first item starts without this pause. Remote acquisition remains serialized, waits remain cancellable, and a failure still stops the remaining items without automatic retries. This application-level pause does not change yt-dlp's internal request pacing.

## Scope and updating

Requirements remain Node.js 22+, system FFmpeg/FFprobe, and the project-managed yt-dlp binary. Save temporary results before stopping LVOVD, update the application, restart the normal launcher, and reload the browser page. The browser still controls final save locations.

There are no new codecs, image formats, hardware encoders, persistent profiles, installers, or processing API changes. Roadmap #7 remains incomplete. Local processing, serialized source acquisition, and localhost security retain their existing boundaries.

## Validation

Regression coverage includes FFprobe success, missing tools, failed and timed-out probes, combined output limits, and bounded termination. Playlist regressions verify the shorter delay bounds, serial acquisition, cancellation during waits, and stopping after failures. Browser scenarios hold removal responses across cleanup completion, another selected file, and a replacement workbench; they verify retained cuts, downloads, jobs, storage reservations, and retry behavior. Runtime status and removal views are checked at desktop and narrow widths on Windows.

Release promotion requires `npm run check`, `npm run test:media`, `npm run test:browser`, `git diff --check`, and the existing Linux and Windows Verify jobs. Local fixtures do not establish compatibility with every public provider.
