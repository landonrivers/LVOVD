# LVOVD v2.6.0 — Local Media Workbench & Batch Processing

LVOVD now brings local editing, conversion, compression, and multiple-file processing together in one **Local Media** workbench. Add local files or selected playlist videos, keep each file's cuts independent, choose output settings, and collect the finished files from one compact results list. Normal URL Download remains a separate workflow.

## One workbench, from source to finished file

- Choose or drop multiple local video/audio files, or use **Edit Source Video** after an eligible single-URL Preview.
- Use **Add Selected to Local Media (N)** after playlist Preview to bring only the chosen video items into the workbench, in Preview order. Import acquires sources; it does not process or save finished files automatically.
- Trim the start/end and remove middle sections with the visual timeline, exact time fields, zoom, and keyboard controls.
- **Process Selected File** applies committed cuts and output settings together directly to the original working source. Final output is not made from a lower-quality playback proxy or an intermediate lossy edited video.

## Conversion and compression

Applicable local outputs include **MP4, MOV, MKV, M4A/AAC, and MP3**. The installed FFmpeg capabilities and each source's inspected media determine which operations are available.

H.264 controls include quality, average bitrate, a maximum complete output size, aspect-preserving resizing, and optional frame-rate reduction. Maximum size uses decimal MB and two-pass encoding with at most one bitrate correction; an output that still exceeds the limit is rejected instead of being published as a truncated file.

Complete unchanged requests use the existing source bytes. Compatible container changes can copy streams without re-encoding; cuts and requested encoding changes may require a re-encode. Results report the effective stream actions and validated output, not merely whether a control was overridden. Re-encoding is not lossless, and arbitrary cuts are not advertised as frame-perfect.

## Independent files and explicit batch processing

Each file keeps its own cuts, pending selections, playhead, zoom, settings, and successful download. **Apply output settings to all** is enabled by default and shares output settings, including the filename suffix, while cuts and playback views remain individual.

**Review All Files → Queue And Process** reviews eligible files and warnings before admitting a sequential batch. Later edits do not rewrite already-queued work. A failed file does not discard other successful results. Cancel controls stop the relevant queued/active work while preserving owned sources and previous successful results where applicable.

## Compact results and Download All

There is one **Processing results** area for single-file and batch output. It comes into view after processing admission without repeatedly moving focus, scrolling, or changing the selected editor during progress updates.

Compact rows show the actual output filename, format, size, duration, and a clear **Download MP3** or equivalent action. Source and encoding details are expandable, and **Edit source** is explicit navigation rather than an ambiguous source-filename link. The list stays bounded and keyboard-scrollable at the 20-file workbench limit.

**Download All (N)** becomes available when all listed latest attempts have completed successfully with matching downloadable outputs. It requests those existing files separately, with their result filenames; it does not create a ZIP, repeat conversion, acquire sources again, or add Download History records. Requests are paced. Removing, replacing, or restarting processing of a captured result stops remaining requests rather than substituting different files. Already-dispatched transfers remain under browser control.

The browser may require permission for multiple downloads. LVOVD reports **downloads requested**, not a guarantee that every file was saved. Individual Download actions remain available. Previous successful files remain clearly labelled after failed/cancelled replacements and do not count as successful outputs of the failed latest attempt.

## Recovery and reliability

- **Previous local workbenches** lets you explicitly reopen retained files/downloads after a page reload, or remove an unused workbench. Draft cuts/settings reset; admitted jobs and successful outputs retain their submitted settings. This is recovery within the same running server, not persistence across a server restart.
- Removed files with unfinished cleanup retain their storage reservation and a reachable scoped retry. Capacity is released only after the owned resources settle and deletion succeeds.
- Playlist cancellation or any acquisition/intake-inspection failure stops later items without automatically retrying them. Completed imports and unrelated files/results are preserved.
- Fixed the oversized progress-buffer feedback loop, which could keep sending unchanged updates after processing had finished. Timeline nodes, focus, and downloads now remain stable through ordinary progress updates.
- Includes the runtime/input-boundary, cleanup, and common-clock audio/video timing hardening accepted since v2.5.0, including preservation of delayed audio, interior gaps, shifted origins, and retained-range timing.

## Limits and privacy

A workbench holds up to **20 files**. The server allows two workbenches, 20 queued/running processing jobs, one upload per workbench, and **100 GiB of aggregate original-source reservations**. This is not a total disk-space guarantee: playback proxies, results, attempts, and pass logs need additional temporary space.

Local output choices do not change remote acquisition. Source work remains serialized, with courtesy pauses for playlist items. **Preview remains the compatibility probe**; generated local fixtures do not prove every public provider/extractor works. Flat-playlist Manual formats and remote audio-only workbench intake remain unsupported.

LVOVD remains local-first, not anonymous. Source services see Preview and acquisition requests from your connection. Default binding remains `127.0.0.1`; this release adds no telemetry, cloud uploads, browser-cookie login support, or DRM/access-control bypass.

Broader local output codecs, local Opus/FLAC/WAV targets, image conversion, hardware encoding, richer track/metadata controls, and desktop packaging remain future work. The existing normal Download audio formats are unchanged. Roadmap #7 is not complete.

A known non-blocking presentation edge remains: an unusually delayed Remove File response can restore an old cleanup sentence in the general status area. It does not itself restore a file or re-reserve released capacity; collection-owned cleanup recovery is separate.

## Updating

Save any temporary results you want to keep **before stopping LVOVD**. Pull the updated `master` branch, or extract this release's source ZIP into a fresh folder, then restart using the normal launcher and reload the browser page. Keep any private plugin/custom files separate when updating; they are not part of this public release.

Requirements remain **Node.js 22+**, system **FFmpeg/FFprobe**, and the project-managed, SHA-256-verified yt-dlp binary. There are no third-party Node runtime dependencies and no new installer or bundled media tools. Developer browser tests use the development-only Playwright dependency. The README Quick Start remains the setup entry point.
